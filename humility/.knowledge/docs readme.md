how to write readme for any repo in the preferred way

# 0.0

readme structure

- name (icon), desc <!-- what -->
- links <!-- where -->
  - docs (index or quick start)
  - roadmap <!-- issues, pm kanban, or purpose -->
  - contributing
  - changes
  - releases
- features <!-- how -->
  - complements
- docs
  - build/deploy/run <!-- how to use, "quick start" -->
  - opinionated choices, mindset, rationales
  - ...

no boilerplate <!-- e.g. literal "features" or "links" -->. only write what's specific and relevant to this repo.

no explanation. do not mix up what and how.

no comparison (why) unless you are marketing

no "quick start" <!-- curl bash --> unless you are marketing, ref docs instead

no internationalization. en only dev. translations are for users, on docs.

repo is on higher level. they might be already viewing this project w that. if not it's fine.

<!-- below are common sense. just in case. -->

desc should be noun phrase. not "(name) is ..."
