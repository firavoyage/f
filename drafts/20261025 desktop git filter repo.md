# how to force remove all large files in git history

### how to force remove all large files in git history

To force remove all large files from your entire Git history, the modern and officially recommended tool is **`git-filter-repo`**. It is significantly faster and safer than the older, deprecated `git filter-branch` command. [](https://stackoverflow.com/questions/2100907/how-can-i-remove-delete-a-large-file-from-the-commit-history-in-the-git-reposito)

Here is the step-by-step guide to purging large files and forcing the changes to your remote repository.

#### Step 1: Install git-filter-repo

If you don't have it installed already, you can quickly grab it using Python's package manager or homebrew:

* **Via Pip:** `pip install git-filter-repo`
* **Via Homebrew (Mac):** `brew install git-filter-repo`

#### Step 2: Make a Fresh Clone (Required)

`git-filter-repo` is destructive and refuses to run on a standard working repository to protect your data. You **must** create a fresh clone of your repository: [](https://www.deployhq.com/git/faqs/removing-large-files-from-git-history)

bash

```
git clone <your-repository-url> repo-cleanup
cd repo-cleanup

```



#### Step 3: Strip All Files Bigger Than a Certain Size

To look at your entire history and strip out every file that exceeds a specific size threshold, use the `--strip-blobs-bigger-than` flag. 

For example, to wipe out all files larger than **50 Megabytes**: 

bash

```
git filter-repo --strip-blobs-bigger-than 50M

```



_(You can change `50M` to `100M` or whatever your threshold is)._ [](https://stackoverflow.com/questions/2100907/how-can-i-remove-delete-a-large-file-from-the-commit-history-in-the-git-reposito)

#### Step 4: Re-add Your Remote Origin

Because `git-filter-repo` completely rewrites your history, it safely removes your remote configuration to prevent accidental pushes. Before you can update GitHub/Bitbucket, you need to re-link your repository:

bash

```
git remote add origin <your-repository-url>

```



#### Step 5: Force Push to the Remote

To overwrite the server's history with your new, optimized history, you must issue a force push. [](https://learn.microsoft.com/en-us/azure/devops/repos/git/remove-binaries?view=azure-devops)

bash

```
git push origin --force --all
git push origin --force --tags

```



_Note: If your main branch is **protected** on GitHub or GitLab, you will need to temporarily unprotect it in your repository's web settings before running this command._ [](https://stackoverflow.com/questions/2100907/how-can-i-remove-delete-a-large-file-from-the-commit-history-in-the-git-reposito)

---

#### 💡 Clean Up Local Space Immediately (Optional)

Your local machine might still hold onto cached objects until Git runs its scheduled background cleanup. If you want to reclaim your local hard drive space immediately, run: [](https://community.atlassian.com/forums/discussion/2491988/how-can-i-clean-large-file-history-in-repository-and-request-to-trigger-gc-on-bitbucket-repository)

bash

```
git reflog expire --expire=now --all
git gc --prune=now --aggressive

```

### do not use this tool, force it manually

To force remove large files manually without using third-party tools like `git-filter-repo` or `bfg`, you must use **`git filter-branch`** (Git's built-in historical rewriter) paired with a script to dynamically identify and purge files over your size limit.

#### Step 1: Find and Purge Large Files Across History

Run the following script in your root Git directory. This loops through every commit, identifies any file larger than **50,000 Kilobytes (50MB)**, and wipes it from history.

bash

```
git filter-branch --force --index-filter '
  git ls-files -s | awk '\''$4 > 51200000 {print $2}'\'' | xargs -I {} git rm --cached --ignore-unmatch "{}"
' --prune-empty --tag-name-filter cat -- --all

```



_(To change the limit, tweak `51200000` bytes to your preferred threshold)._

#### Step 2: Reclaim Space and Delete the Backup Reflogs

Git keeps a backup copy of your old history in its internal logs (`refs/original/`). To permanently delete these backups and reclaim your hard drive space right now, execute:

bash

```
# Remove the filter-branch backup references
rm -rf .git/refs/original/

# Expire all reflogs so the old commits are orphaned
git reflog expire --expire=now --all

# Force garbage collection to permanently delete the files
git gc --prune=now --aggressive
```
