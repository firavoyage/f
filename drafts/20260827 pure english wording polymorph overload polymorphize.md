The primary difference is their part of speech.

- **Polymorph** is traditionally used as a **noun** or an **adjective**. It describes an organism, molecule, or object that exhibits multiple forms or states.

## compare polymorph and polymorphize in swe

In software engineering (SWE), **polymorph** and **polymorphize** represent two entirely different stages of the development lifecycle. A **polymorph** is a design-time architectural concept written by a developer, while **polymorphize** is a compile-time optimization process performed by a compiler. [link](https://internals.rust-lang.org/t/add-back-polymorphization/22879)

***

### Core Comparison

| Feature             | Polymorph (Design Concept)                                                | Polymorphize (Compiler Optimization)                                          |
| ------------------- | ------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| **Primary Actor**   | **Software Engineer**                                                     | **The Compiler** (e.g., `rustc`)                                              |
| **Lifecycle Phase** | Source code architecture / writing                                        | Code compilation / binary generation                                          |
| **Objective**       | Write clean, reusable, abstract code                                      | Reduce binary bloat caused by generics                                        |
| **How it works**    | Creating types or methods that take multiple forms (Subtyping, Generics). | Merging identical generic implementations into one block.                     |
| **Example**         | `fn process_data<T>(input: T)`                                            | Detecting that `T` isn't used in a specific block and compiling it only once. |

***

### 1. Polymorph: The Developer's Design Pattern

When you write a **polymorph** (or use _polymorphism_), you are implementing a fundamental pillar of object-oriented programming (OOP) or functional programming. It allows different data types to be handled through a uniform interface. [link](https://www.youtube.com/watch?v=y0zQsLJev88\&t=382)

Engineers create polymorphic code using:

- **Subtype Polymorphism:** Writing an interface or abstract class (e.g., a `Shape` interface implemented by `Circle` and `Square`).
- **Parametric Polymorphism (Generics):** Writing functions or structs with placeholder types (e.g., `List<T>`), allowing a single codebase to handle various types dynamically. [link](https://softwareengineering.stackexchange.com/questions/418872/what-is-polymorphism)

### 2. Polymorphize: The Compiler's Binary Optimization

**Polymorphize** (often called _polymorphization_) is a highly specific optimization pass found in system compilers, most notably in the **[Rust compiler (`rustc`)](https://internals.rust-lang.org/t/add-back-polymorphization/22879)**. [link](https://github.com/rust-lang/compiler-team/issues/810)

To understand polymorphization, you must first understand **monomorphization**. When you use generics, compilers usually duplicate the code for every distinct type used (e.g., creating separate binary blocks for `my_function::<i32>` and `my_function::<String>`). This ensures excellent runtime performance but causes **binary size bloat**. [link](https://medium.com/@kaly.salas.7/rust-performance-optimizations-compared-to-other-programming-languages-c2e3685163e2)

- **The Fix:** The compiler will **polymorphize** the function by scanning the generic code. If it notices that a specific type parameter `T` is completely unused inside a segment of code (or an inner function), it strips the duplication. [link](https://internals.rust-lang.org/t/idea-would-rust-benefit-from-explicitly-polymorphic-generics/18257?page=2)
- **The Result:** Instead of generating 100 identical versions of a compiled function for 100 different types, it compiles it exactly **once**, sharply reducing code size and bundle overhead. [link](https://internals.rust-lang.org/t/add-back-polymorphization/22879)
